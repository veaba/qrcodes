## 性能测试结果

### 三者对比

以下为权威数据文件 [`benchmark_speedup_verified.json`](https://github.com/veaba/qrcodes/blob/main/docs/public/benchmark_speedup_verified.json) 的完整内容（2026-03-20，Windows x64，rustc 1.89.0）。

**测量口径**：端到端 SVG 生成（`make_code` + `get_svg()` / kennytm 的 `render().build()`），三方实现同一进程内依次测量，
每用例预热 20 次后重复 100 次取算术平均值，产物经 resvg + rqrr 独立解码验证。

**复现命令**：

```bash
cd bench/rust-tools && cargo run --release --bin verify-speedup
```

| 用例 | 文本长度 | qrcode-rust | qrcode-fast | kennytm-qrcode | rust vs kennytm | fast vs kennytm | fast vs rust |
|------|---------|-------------|-------------|----------------|-----------------|-----------------|--------------|
| Simple (`Hello World`) | 11 B | ~32.1 µs | **~18.5 µs** | ~210.4 µs | **6.6x** | **11.4x** | **1.74x** |
| Complex (`Test QR Code 123`) | 17 B | ~41.3 µs | **~19.8 µs** | ~324.1 µs | **7.8x** | **16.2x** | **2.08x** |
| URL (`https://github.com/veaba/qrcodes`) | 31 B | ~53.2 µs | **~24.2 µs** | ~453.3 µs | **8.5x** | **18.8x** | **2.20x** |
| Long (74 B) | 74 B | ~130.2 µs | **~64.4 µs** | ~826.2 µs | **6.2x** | **12.5x** | **2.02x** |

**汇总区间**：`qrcode-fast` vs `kennytm-qrcode` **9-19x**，`qrcode-rust` vs `kennytm-qrcode` **6-9x**，`qrcode-fast` vs `qrcode-rust` **1.5-2.2x**。

> ⚠️ 这些倍率是**单机单次测量**结果，不同 CPU / 编译器版本会有差异，应视为量级参考而非精确承诺。
> 「快多少倍」取决于输入长度与用例：实测最低值出现在 `SiteUrl`（25 B，fast vs rust 1.47x），
> 最高值出现在原 `URL` 用例（31 B，fast vs kennytm 18.8x）。

### 本轮未测量的维度

**验证结论**: 
- `qrcode-rust` 生成的二维码 SVG 可以通过标准二维码扫描器正确解码，内容匹配
- `qrcode-fast` 生成的二维码也可正确解码

### 与 kennytm-qrcode 的兼容性

| 测试内容 | 结果 | 说明 |
|---------|------|------|
| "Hello World" (v1) | ✅ 完全匹配 | 模块矩阵与 kennytm 完全一致 |
| "Test QR Code 123" (v2) | ✅ 验证通过 | 使用 mask pattern 0，可正确扫描 |
| 格式信息 | ✅ 正确放置 | 水平和垂直格式信息位置与 kennytm 一致 |
| Mask Pattern | ✅ 正确应用 | Mask pattern 0: `(row + col) % 2 == 0` |

### 关键修复 (2026-02-02)

   - 垂直方向（第8列）：从上到下正确放置
   - 水平方向（第8行）：从右到左正确放置

## 技术细节

### 测试方法

本页权威数字使用 `bench/rust-tools` 的 `verify-speedup`：
- 预热次数: 20 次/用例
- 采样次数: 100 次/用例
- 统计量: 算术平均值
- 口径: 端到端 SVG 生成（`make_code` + `get_svg()` / `render().build()`）
- 正确性: resvg 渲染 + rqrr 独立解码

此外 `packages/qrcode-rust` 下另有基于 Criterion.rs 的微基准（预热 3 秒，约 5 秒/测试），
其结果不与本页倍率混用。

### 测试数据

本页权威表格（`verify-speedup`）使用的四个用例：

- Simple: `"Hello World"` (11 字节)
- Complex: `"Test QR Code 123"` (17 字节)
- URL: `"https://github.com/veaba/qrcodes"` (31 字节)
- Long: `"Email: test@example.com | Phone: +1-234-567-8900 | Address: 123 Main St"` (74 字节)

> 历史版本此处列的是短/中/长三档（12 / 36 / 98 字符），那是 Criterion 微基准的输入，
> 与本页权威表格的四个用例不同，不要对应。

> ✅ 关于解码能力：`benchmark_speedup_verified.json` 的 `capability` 说明两个 Rust 包现已覆盖
> **全部 40 个版本，H 级最大 1273 字节**（QR 标准上限），与 JS 实现一致。
> 此前的长度限制（`qrcode-fast` 约 110 字节、`qrcode-rust` 约 60 字节）与实例复用缺陷均已修复，
> 详见该文件的 `fixed_defects`。复现：`cargo run --release --features validation --bin scan-max`。

### SVG 验证工具

位于 `bench/rust-tools`，提供以下功能：
- `validate-qr` - 生成并验证二维码
- `scan-max` - 逐点扫描最大可解码长度（1..1400 字节）+ 独立解码验证
- `verify-capacity-table` - 容量表 vs QR 标准（160 项，含边界行为断言）
- `check-min-version` - 校验版本选择与容量表边界
- `verify-speedup` - 三方端到端性能验证（权威口径）
- `compare_matrix` - 对比模块矩阵与 kennytm
- `compare_matrix_v1` - 对比版本 1 的矩阵
