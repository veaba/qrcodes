## 测试概述

本基准测试对比了以下 Rust QRCode 生成库的 SVG 生成性能：

| 包                   | 描述                                  | 状态                  |
| -------------------- | ------------------------------------- | --------------------- |
| `kennytm-qrcode`     | 社区流行的 Rust QRCode 库（参考基准） | ✅ 四用例均有效       |
| `@veaba/qrcode-rust` | 纯 Rust 实现，功能完整                | ⚠️ 见下方「验证状态」 |
| `@veaba/qrcode-fast` | 极致性能优化版本，功能完整            | ⚠️ 见下方「验证状态」 |

> ⚠️ 本页数据来自 **SVG 专项 harness**（[`benchmark_svg_rust.json`](https://github.com/veaba/qrcodes/blob/main/docs/public/benchmark_svg_rust.json)），**不是**全仓库的权威口径。
> 权威数据是 [`benchmark_speedup_verified.json`](https://github.com/veaba/qrcodes/blob/main/docs/public/benchmark_speedup_verified.json)（端到端 SVG，`qrcode-fast` 比 kennytm 快 **9-19 倍**、
> `qrcode-rust` 快 **6-9 倍**）。两套数字口径不同，**请勿混用**，详见下方「性能对比」的警告。

## 主要发现

### 🏆 性能冠军

`@veaba/qrcode-fast` 在两个数据源中都是最快的实现：

- **权威口径**（[`benchmark_speedup_verified.json`](https://github.com/veaba/qrcodes/blob/main/docs/public/benchmark_speedup_verified.json)，端到端 SVG）：比 `kennytm-qrcode` 快 **9-19 倍**，比 `@veaba/qrcode-rust` 快 **1.5-2.2 倍**
- **本页 SVG 专项口径**（[`benchmark_svg_rust.json`](https://github.com/veaba/qrcodes/blob/main/docs/public/benchmark_svg_rust.json)）：比 `kennytm-qrcode` 快 **19.8-22.4 倍**，比 `@veaba/qrcode-rust` 快约 **2.3-2.6 倍**

> 两套数字的差异来自热身方式、计时范围与输入文本不同，**不可混用**。
> 对外表述与选型请使用权威口径的 **9-19 倍 / 6-9 倍**。

### ✅ 验证状态

**本页数据文件（`benchmark_svg_rust.json`）中的状态并非全部通过**：Simple 与 URL 两例有效，
Complex 与 Long 两例的 `qrcode-rust` / `qrcode-fast` 均标记为 `valid: false`（详见上方「验证状态」表）。

当前版本的正确性验证结果以 `benchmark_speedup_verified.json` 为准 —— 其四个用例（11 / 17 / 31 / 74 字节）
经 resvg + rqrr 独立解码均能还原原文。

- `kennytm-qrcode`: 社区成熟实现，稳定可靠
- `qrcode-rust`: 功能完整，与 kennytm 参考实现保持一致；⚠️ 约 60 字节以上存在解码失败问题
- `qrcode-fast`: 极致性能优化，功能完整；⚠️ 约 110 字节以上存在解码失败问题

### 为什么要先统一纠错级别

直接对比五方会得到**不公平**的结果：`@veaba/qrcode-fast` / `@veaba/qrcode-rust` 默认使用 **H 级（30% 纠错）**，
而 `kennytm-qrcode` 默认使用 **M 级（15% 纠错）**。同一段 `hello world`，veaba 系产出 25×25 模块，
kennytm 仅 21×21 —— 相当于让 kennytm 做更小的活。

因此本节**统一到纠错级别 M**。实测确认五方产物模块数完全一致（21 / 25 / 45），差异才可归因于实现效率。

#### 自动校验这些 SVG（推荐，替代人工逐个扫码）

```bash

# 底层工具：直接指定目录

```

该工具按文件名解析出「实现 + 用例」，用 `resvg` 渲染 + `rqrr` 解码还原文本并与原始输入比对，

> 注意直接调用 `cargo run` 时要带 `--features validation`，否则解码函数会返回「未启用验证特性」。
> 走 `pnpm run bench:svg:validate` 则已包含该参数。

#### ✅ 已修复缺陷：两个实现曾产出不可解码的二维码

`validate-svg-dir` 首次运行即发现真实缺陷（用**独立解码器** `resvg` + `rqrr` 确认），
现已全部修复：

**缺陷 1 — `qrcode-bun` 缺版本信息（v7+ 不可解码）**

| 实现 | Version ≤ 6 | Version ≥ 7 | 修复后 |
| ---- | ----------- | ----------- | ------ |
| `qrcode-fast` / `qrcode-rust` / `kennytm` | ✅ | ✅ | ✅ |
| `@veaba/qrcode-node` | ✅ | ✅ | ✅ |
| **`@veaba/qrcode-bun`** | ✅ | ❌ **`DataEcc`** | ✅ **已修复** |

- 边界：58 字节（v6）通过，59 字节（v7）失败；`qrcode-node` 同版本通过，故缺陷在 bun 自身。
- 根因：`packages/qrcode-bun/src/index.ts` 的 `setupTypeNumber()` 是**空实现**（仅有 `// 简化版本` 注释），
  v7+ 缺少 18 位版本信息，解码器无法判定版本。
- 修复：实现 BCH(18,6) 版本信息写入（生成多项式 `G18 = 0x1F25`），
  右上 / 左下各写一份，与 `qrcode-js-shared` / `qrcode-fast` 的既有实现一致。

**缺陷 2 — 对齐图案坐标表从 v22 起整体错位（影响 node 与 bun）**

- 现象：`qrcode-node` 在 v22+ 不可解码（440 字节起失败），`qrcode-bun` 在 v23+ 失败。
- 根因：`PATTERN_POSITION_TABLE` 含 **41** 条记录（应为 40），
  多出一条重复的 `[6, 28, 50, 72, 98]`，导致 v22 及以后每个版本都取到**下一个版本**的坐标。
  表内 v40 实为 v39 的值，v40 真实坐标缺失。
- 修复：删除重复行，并用 QR 标准（ISO 18004 Annex E）坐标校正 v22–v40。
  现 40 个版本与标准**逐项吻合**。
- 该表在 `qrcode-js-shared` 与 `qrcode-bun` 各有一份副本，**两处都已修复**。

**修复后验证**

```bash
cargo run --release --features validation --bin validate-svg-dir
# ✅ 全部 75 个 SVG 均可被独立解码器还原为原始文本
```

另经逐版本扫描（v7 → v40，59 → 1273 字节）：`node` 与 `bun` **24/24 全部通过**，
覆盖到 QR 标准 H 级上限 1273 字节。

> 回归测试已固化于 `bench/rust-tools/tests/qr_validity.rs::persisted_svgs_all_decode`，
> 五方 × 三用例全量断言，**不再豁免任何实现**。

### ⚠️ 口径限制（请勿横向解读本表）

本表**不是**「运行时优劣」排行榜：

1. **Rust 三方同进程可比**，可信度最高。
2. **`qrcode-node` 与 `qrcode-bun` 是两套不同实现** —— 前者封装 `@veaba/qrcode-js-shared` 的 `QRCodeCore`，
   后者自带独立实现。因此 `qrcode-bun` 快于 `qrcode-node` **主要反映实现差异，不能归因于 Bun 运行时更快**。
3. **跨语言（JS vs Rust）的倍数不予提供**：不同进程、不同 GC/JIT、不同计时原语
   （`performance.now()` vs `Instant::now()`），相除得到的倍数没有意义。

### 复现命令

一条命令即可跑完三个 harness 并写入数据文件（**推荐**）：

```bash
# 采集五方数据 → docs/public/benchmark_svg_five_way.json
pnpm bench:svg:five-way
# 或
node bench/svg-benchmark/collect-five-way.mjs
```

也可单独运行每个 harness：

```bash
# Rust 三方（统一 M 级，同进程）
cargo run --release --bin five-way-rust-m --manifest-path bench/rust-tools/Cargo.toml

# Node / Bun 两方（统一 M 级，各自独立进程）
node bench/svg-benchmark/five-way-js.mjs --target=node --ec=M
bun  bench/svg-benchmark/five-way-js.mjs --target=bun  --ec=M
```

> 采集器会校验各实现在同一用例下的**模块数是否一致**；不一致说明纠错级别没对齐，
> 它会以退出码 1 报告，此时跨实现的比较无效。
>
> 未安装 Bun 时可加 `--skip-bun`（图表会自动隐藏该行）；想复用已编译的 Rust 产物可加 `--skip-rust`。
>
> 不带 `--ec=M` / 使用 `--bin five-way-rust` 可复现「未对齐纠错级别」的原始结果，
> 用于观察默认级别差异带来的产物规模变化。

### 生成权威口径数据 + SVG 落盘（H 级）

**推荐：一条命令跑完「五方生成 + 独立解码校验」**

```bash
pnpm run bench:svg:gen          # 每实现每用例落 5 次，末尾自动校验
pnpm run bench:svg:gen:all      # 每实现每用例落 100 次
pnpm run bench:svg:gen -- --keep        # 保留旧文件，不先清空
pnpm run bench:svg:gen -- --skip-bun    # 未安装 Bun 时
pnpm run bench:svg:gen -- --no-validate # 只生成不校验
```

校验全部通过退出码 0；任一 SVG 无法解码则退出码 1（便于接入 CI）。
只做校验（不重新生成）：

```bash
pnpm run bench:svg:validate
```

**分步执行（需要单独跑某一方时）**

```bash
# Rust 三方：写入权威三用例数据，并落盘 SVG 到 docs/public/bench/svg/
cargo run --release --bin five-way-rust-h --manifest-path bench/rust-tools/Cargo.toml
# 落盘全部 100 次（默认只落前 5 次）
cargo run --release --bin five-way-rust-h --manifest-path bench/rust-tools/Cargo.toml -- --save-all

# Node / Bun 两方（H 级 + 落盘 SVG）
node bench/svg-benchmark/five-way-js.mjs --target=node --ec=H --save-svg
bun  bench/svg-benchmark/five-way-js.mjs --target=bun  --ec=H --save-svg
```

> ⚠️ Node 侧按路径导入 `packages/qrcode-node/dist/index.js`。
> 若改动了 `qrcode-js-shared`，需先重新构建，否则测到的仍是旧产物：
> `pnpm --filter @veaba/qrcode-js-shared build && pnpm --filter @veaba/qrcode-node build`

## 使用建议

### 按场景推荐

| 场景       | 推荐                                         | 原因                                                 |
| ---------- | -------------------------------------------- | ---------------------------------------------------- |
| 极致性能   | `@veaba/qrcode-fast`                         | 最快的生成速度，比 kennytm 快 9-19 倍（权威口径）   |
| 通用场景   | `@veaba/qrcode-rust`                         | 功能完整，性能优秀，比 kennytm 快 6-9 倍（权威口径） |
| 兼容性优先 | `kennytm-qrcode`                             | 社区成熟，文档丰富                                   |
| WASM 场景  | `@veaba/qrcode-rust` 或 `@veaba/qrcode-fast` | 两者都支持 WASM                                      |

### 版本选择建议

✅ 两个 Rust 包现已覆盖**全部 40 个版本，H 级最大 1273 字节**（QR 标准上限），与 JS 实现一致；
此前的解码边界问题（`qrcode-rust` 约 60 字节、`qrcode-fast` 约 110 字节）均已修复，
详见 [`benchmark_speedup_verified.json`](https://github.com/veaba/qrcodes/blob/main/docs/public/benchmark_speedup_verified.json) 的 `capability` 与 `fixed_defects`。

| 文本长度               | 推荐包                                       | 说明                                               |
| ---------------------- | -------------------------------------------- | -------------------------------------------------- |
| < 20 字符（版本 1-2）  | `@veaba/qrcode-fast`                         | 性能最佳                                           |
| 20-50 字符（版本 3-5） | `@veaba/qrcode-fast` 或 `@veaba/qrcode-rust` | 两者都验证通过                                     |
| > 50 字符（版本 6+）   | `@veaba/qrcode-fast`                         | ✅ 已验证；覆盖至 Version 40（H 级 1273 字节上限） |

### 纠错级别建议

所有包在所有纠错级别（L/M/Q/H）**枚举上均可用**，但请注意：**本轮没有重新测量按纠错级别分组的性能**，
权威数据文件 `benchmark_speedup_verified.json` 的四个用例均使用默认的 H 级别。
本页历史版本给出的 L/M/Q/H 性能表已删除（来源不可复现）。

## 历史问题（已修复）

### 2026-02-02 之前的验证失败问题

在早期版本中，`@veaba/qrcode-rust` 和 `@veaba/qrcode-fast` 在某些复杂文本上验证失败，错误类型为 `DataEcc`（Reed-Solomon 纠错码错误）。

#### 问题原因

1. **格式信息放置错误**：水平和垂直格式信息的位置不正确
2. **Mask Pattern 应用错误**：mask pattern 的公式应用有误

#### 修复内容

1. **格式信息放置修复**
   - 垂直方向（第8列）：从上到下正确放置
   - 水平方向（第8行）：从右到左正确放置
   - 正确处理 test 模式

2. **Mask Pattern 修复**
   - 统一使用 mask pattern 0: `(row + col) % 2 == 0`
   - 确保与 kennytm 的默认选择一致

#### 修复验证

以下结论来自 `benchmark_speedup_verified.json`（权威口径，四个用例经 resvg + rqrr 解码验证）：

- ✅ "Hello World" (11 B)：解码还原成功
- ✅ "Test QR Code 123" (17 B)：解码还原成功
- ✅ URL (31 B) 与 Long (74 B)：解码还原成功

> ✅ 现已彻底修复：`qrcode-fast` 与 `qrcode-rust` 均覆盖全部 40 个版本（H 级最大 1273 字节），
